# Maniforge WMS — UI сканера (спецификация, без реализации)

Документ описывает **мобильный/терминальный интерфейс** для операций склада на базе существующего API `/wms` и `/inventory`.  
**Внешние интеграции не используются** (нет онлайн-проверки Честный ЗНАК, нет обмена с ГИС МТ). Валидация КИЗ — только локальный разбор `KizParser` и справочник `maniforge_wms_marking_codes`.

Реализация UI **не входит в scope** этого репозитория; ниже — макет поведения для фронтенда (PWA, React, нативное приложение ТСД).

---

## 1. Роли и доступ

| Роль | Экраны | Permissions |
|------|--------|-------------|
| Кладовщик | Приёмка, отгрузка, скан-инфо | `wms.read`, `wms.write`, `inventory.read`, `inventory.write` |
| Маркировщик | Регистрация КИЗ, сборка ГУ, seal | `wms.write` |
| Админ | Справочники, сторно (отдельный экран) | + `inventory.write` |

Сессия: Bearer token RBAC, контекст `tenant_id` + `subtenant_id` + активный `project_id` (как в остальных модулях Maniforge).

---

## 2. Общие принципы UX

1. **Один фокус — поле скана** (autofocus, fullscreen на ТСД).
2. **Звук/вибрация**: успех (короткий), ошибка (длинный), дубликат (двойной).
3. **Крупный шрифт** (мин. 18px), контраст WCAG AA.
4. **Офлайн (v2)**: в MVP только online; очередь сканов — не реализуется в backend сейчас.
5. После каждого скана — **мгновенный preview** (`GET/POST /wms/api/v1/scan`) до подтверждения операции.

### Ввод кода

| Источник | Поведение |
|----------|-----------|
| Камера (1D/2D) | DataMatrix КИЗ, QR паллеты, Code128 SSCC, **EAN-13** |
| Лазерный сканер (HID) | Эмуляция клавиатуры → то же поле, Enter = отправить |
| Ручной ввод | Кнопка «Клавиатура» для редких случаев |

Нормализация: trim, не менять регистр КИЗ; QR паллеты — полная JSON-строка как с бэкенда.

## 3. Карта экранов

```text
┌─────────────┐
│  Hub (глав) │
└──────┬──────┘
       ├──► Скан-инфо (lookup)
       ├──► Приёмка
       ├──► Отгрузка
       ├──► Сборка ГУ (агрегация КИЗ)
       ├──► Паллета (вложение + seal)
       └──► Настройки (склад, проект)
```

---

## 4. Экран: Hub

**Цель:** выбор операции и контекста склада.

**Элементы:**
- Dropdown **Узел склада** (`stock_id`) — список из `GET /warehouses/api/v1/stocks?type=zone` (или warehouse → drill-down).
- Chip **Проект** (readonly из сессии).
- Кнопки-карточки: Приёмка | Отгрузка | Сборка ГУ | Паллета | Скан-инфо.
- Footer: пользователь, tenant, «Выйти».

**Сохранение:** `localStorage.wms_scanner_ctx = { stock_id, last_operation }`.

---

## 5. Экран: Скан-инфо (lookup)

**Поток:**
1. Поле скана (автофокус).
2. `POST /wms/api/v1/scan` body `{ "code": "<scanned>" }`.
3. Отрисовка карточки:
   - **kind=product**: EAN-13, название SKU, `product_id` — приёмка/отгрузка с полем `qty`.
   - **kind=marking**: код, GTIN, serial, product name, status (`available` / `in_group` / `on_pallet` / `shipped`).
   - **kind=pack**: type, code, SSCC, status, QR preview (мини), таблица contents (N КИЗ / M дочерних ГУ).

**Действия (контекстные):**
- marking + `available` → CTA «Добавить в текущую ГУ» (если открыта сессия сборки).
- pack + `sealed` → CTA «Принять на склад» → переход на Приёмку с prefill.

**Ошибки:**

| API | UI |
|-----|-----|
| 404 | «Код не найден» + повторить скан |
| 403 | «Нет доступа» |

---

## 6. Экран: Приёмка

**Предусловие:** выбран `stock_id` на Hub.

**Поток A — паллета / ГУ:**
1. Скан SSCC, QR или код упаковки.
2. Scan API → `kind=pack`, status=`sealed`.
3. Preview: «Принять паллету PLT-xxx, 120 КИЗ, 3 SKU?» (агрегат из contents — опционально второй запрос `GET /wms/api/v1/packs/{id}`).
4. Кнопка **Подтвердить** → `POST /wms/api/v1/movements/scan`:
```json
{
  "movement_type": "receipt",
  "stock_id": 42,
  "scan": "<payload>",
  "doc_number": "rcv-scanner-20260603-001"
}
```
5. Успех: зелёный экран, счётчик «Принято паллет: N», кнопка «Следующий скан».

**Поток B — одиночный КИЗ** (если без паллеты):
- Тот же endpoint с `scan` = КИЗ, одна строка +1.

**Ошибки:**

| code | UI |
|------|-----|
| `pack_not_sealed` | «Упаковка не запечатана» |
| `insufficient_qty` | не при приёмке |
| 409 duplicate doc | предложить новый doc_number |

---

## 7. Экран: Отгрузка

**Поток:**
1. Скан КИЗ или sealed pack (как при приёмке, но `movement_type: issue`).
2. Preview: «Списать 1 шт. SKU-xxx с зоны Z-01?»
3. Confirm → `POST /wms/api/v1/movements/scan` с `issue`.
4. При `insufficient_qty` — красный баннер «Нет остатка».

**Паллета целиком:** scan паллеты → explode все КИЗ → issue по строкам (как в journey).

---

## 8. Экран: Сборка групповой упаковки (ГУ)

**Состояние сессии (клиент):** `draft_pack_id` — создаётся при «Новая ГУ».

**Поток:**
1. **Новая ГУ** → `POST /wms/api/v1/packs` `{ "unit_type": "group", "code": "gu-<timestamp>" }` → сохранить `id`.
2. Цикл скана КИЗ:
   - Если КИЗ нет в БД → модал «Зарегистрировать?» → `POST /wms/api/v1/markings` или bulk позже.
   - `POST /wms/api/v1/packs/{id}/markings` `{ "code": "..." }`.
   - Счётчик «В ГУ: 12 шт.» + список последних 5 кодов (маска serial).
3. **Запечатать** → `POST /wms/api/v1/packs/{id}/seal` → показать QR/код для печати этикетки (опционально: рендер QR из `pack.qr_payload`).

**Отмена черновика:** только пока `status=draft` — удаление не в API; UI может предупреждать «бросить» без seal.

**Дизагрегация** (отдельная кнопка в админ-режиме): `POST /packs/{id}/disaggregate` для `sealed`/`at_stock`.

---

## 9. Экран: Паллета

**Поток:**
1. `POST /wms/api/v1/packs` `{ "unit_type": "pallet", "stock_id": <zone> }` → SSCC auto.
2. Скан **запечатанной** ГУ (QR/code) → `POST /packs/{palletId}/children` `{ "child_pack_unit_id": ... }`.
3. Счётчик вложений на паллете.
4. **Seal pallet** → QR + SSCC на экране + «Печать» (window.print или PNG).
5. CTA «Принять на склад» → переход в Приёмку.

---

## 10. Экран: Сторно (опционально, desktop/tablet)

Не сканер по умолчанию; для супервизора.

1. Поиск документа `GET /inventory/api/v1/movements?limit=20`.
2. Карточка движения → **Сторнировать** → `POST /inventory/api/v1/movements/{id}/reverse`.
3. Подтверждение: «Будет создан документ xxx-rev-xxxx, остатки откатятся, КИЗ вернут статус».

Связь WMS: backend сам вызывает `syncAfterMovementReversal` при строках с `marking_code_id`.

---

## 11. API-матрица (сканер)

| Действие UI | Endpoint |
|-------------|----------|
| Разрешить код | `POST /wms/api/v1/scan` |
| Приёмка/отгрузка | `POST /wms/api/v1/movements/scan` |
| Новая ГУ/паллета | `POST /wms/api/v1/packs` |
| +КИЗ в ГУ | `POST /wms/api/v1/packs/{id}/markings` |
| +ГУ в паллету | `POST /wms/api/v1/packs/{id}/children` |
| Seal | `POST /wms/api/v1/packs/{id}/seal` |
| Регистрация КИЗ | `POST /wms/api/v1/markings` или `/markings/bulk` |
| Список остатков | `GET /inventory/api/v1/balances?stock_id=&non_zero=1` |
| Сторно | `POST /inventory/api/v1/movements/{id}/reverse` |

## 12. Состояния КИЗ (индикаторы UI)

| status | Цвет | Подпись |
|--------|------|---------|
| `available` | зелёный | Свободен |
| `in_group` | синий | В групповой |
| `on_pallet` | фиолетовый | На складе (в составе) |
| `shipped` | серый | Отгружен |

## 14. Нефункциональные требования

| Параметр | Цель |
|----------|------|
| Latency scan → preview | < 300 ms LAN |
| Debounce скана | 100 ms (дедуп одинакового кода 2 с) |
| Таймаут API | 15 s, retry ×1 |
| Локаль | ru-RU |

---

## 15. Печать этикеток (без интеграции)

- **ГУ:** QR с `pack.qr_payload` (если consumer/group без SSCC — code128 `pack.code`).
- **Паллета:** QR JSON + текст SSCC EAN128.
- Генерация на клиенте (qrcode.js / label template 58×40 mm).

---

## 16. Что сознательно не делаем

- Онлайн-проверка в ЧЗ / ERP.
- Офлайн-очередь и conflict resolution.
- Фото и видео фиксация.
- BLE-весы (v2).
